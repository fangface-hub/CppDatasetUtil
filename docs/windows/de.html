CppDatasetUtil API

NAME

CppDataSet - rekursiver Dataset-Wert mit optionalen Kommentaren

ÜBERSICHT

#include <Dataset.h>
class Dataset;

BESCHREIBUNG

Dataset enthält null, bool, eine vorzeichenbehaftete 64-Bit-Ganzzahl, double, eine Zeichenkette, eine Map oder ein Array. Map- und Array-Elemente sind ebenfalls Dataset-Werte. Jeder Wert kann eigene Kommentare tragen. Maps sind nach Schlüsseln sortiert, Arrays behalten ihre Reihenfolge. Kopieren und Verschieben übernehmen sowohl Werte als auch Kommentare.

TYPEN UND KONSTRUKTOREN

Dataset::Map ist std::map<std::string, Dataset>, Dataset::Array ist std::vector<Dataset> und Dataset::Value ist eine std::variant der unterstützten Typen. Der Standardkonstruktor erzeugt null ohne Kommentare. Konstruktoren akzeptieren nullptr, bool, int, std::int64_t, double, const char*, std::string, Map und Array. Ein null-Zeiger für const char* führt zu std::invalid_argument.

Jeder andere Ganzzahltyp, etwa long long, std::size_t oder unsigned, wird als vorzeichenbehaftete 64-Bit-Ganzzahl gespeichert; ein vorzeichenloser Wert über dem int64-Bereich führt zu std::out_of_range. Andere Zeiger als const char* werden zur Compilezeit abgelehnt, statt zu bool zu werden.

ZUGRIFF

operator[](const std::string& key) Greift auf einen Map-Eintrag zu. Bei einem veränderbaren null-Wert wird eine leere Map erzeugt; ein fehlender Schlüssel wird mit null eingefügt. Kommentare des übergeordneten Werts bleiben erhalten. Const-Zugriff ändert nichts und wirft std::out_of_range bei fehlendem Schlüssel. Ein Wert, der keine Map ist, führt zu std::logic_error.

operator[](std::size_t index) Greift auf ein Array-Element zu, ohne es einzufügen. Der Index beginnt bei 0. Ein anderer Typ führt zu std::logic_error, ein ungültiger Index zu std::out_of_range. Ersetzen des übergeordneten Dataset macht Referenzen auf seine Elemente ungültig.

value() const noexcept Liefert eine const-Referenz auf Value. std::get wirft bei falschem Typ std::bad_variant_access; std::get_if liefert dann einen null-Zeiger.

size() const noexcept Liefert die Anzahl der Einträge einer Map oder eines Arrays, für jeden anderen Wert 0.

contains(const std::string& key) const noexcept Liefert true, wenn der Wert eine Map ist, die key enthält.

push_back(Dataset value) Hängt ein Element an ein Array an. Ein null-Wert wird zuvor zu einem leeren Array und behält seine Kommentare. Jeder andere Typ führt zu std::logic_error.

erase(const std::string& key) Entfernt einen Map-Eintrag und liefert, ob er existierte. Ein Wert, der keine Map ist, führt zu std::logic_error.

erase(std::size_t index) Entfernt ein Array-Element; spätere Elemente rücken nach. Ein anderer Typ führt zu std::logic_error, ein ungültiger Index zu std::out_of_range.

value() noexcept Liefert eine veränderbare Referenz auf Value. Zuweisen einer anderen Alternative ersetzt den Wert; die Kommentare bleiben erhalten.

operator==, operator!= Vergleichen Werte und Kommentare rekursiv. Ein NaN ist nie gleich sich selbst.

KOMMENTARE

comments() const noexcept Liefert eine const-Referenz auf die Kommentare in gespeicherter Reihenfolge.

set_comments(std::vector<std::string> comments) Ersetzt die Kommentare. Text wird ohne führendes # angegeben; Zeilenumbrüche erzeugen mehrere Kommentarzeilen. YAML und TOML verlangen gültiges UTF-8 und weisen nicht unterstützte Steuerzeichen und Unicode-Zeilentrenner zurück. In TOML syntaktisch nicht darstellbare Kommentare werden ausgelassen. CSV und JSON speichern keine Kommentare. Zuweisung und erfolgreiches Load ersetzen vorhandene Kommentare.

DATEIEN

Load(const std::string& path) Lädt CSV, JSON, YAML oder TOML anhand der Erweiterung .csv, .json, .yaml, .yml oder .toml, unabhängig von Groß- und Kleinschreibung. Kommentare werden nicht eingelesen. Erfolg ersetzt Wert und Kommentare; bei Fehlern bleibt das Dataset unverändert. E/A-Fehler, ungültige Eingaben und nicht unterstützte Erweiterungen oder Werte führen zu std::runtime_error.

static Parse(const std::string& text, const std::string& format = "json") Parst CSV-, JSON-, YAML- oder TOML-Text. format ist ein Name ohne Beachtung der Groß- und Kleinschreibung: csv, json, yaml, yml oder toml (Standard json). Es gelten die Regeln von Load einschließlich der Verschachtelungsgrenze, jedoch ohne Kommentare. Damit lässt sich die Zeichenkette auflösen, die für tiefer verschachtelte Werte erhalten bleibt. Ungültige Eingaben oder ein nicht unterstütztes Format führen zu std::runtime_error.

static LoadDirectory(const std::string& path, bool recursive = false) Liefert eine nach Pfad sortierte std::list von Paaren aus Pfad und Dataset. Unterverzeichnisse werden nur bei recursive=true durchsucht. Nicht unterstützte Erweiterungen werden ignoriert. Symbolischen Links auf Dateien und Verzeichnisse wird gefolgt; dasselbe Ziel wird für jeden erreichbaren Pfad geladen. Die zurückgegebenen Pfade behalten die angegebenen Verzeichnis- und Linknamen. Bei Dateilinks bestimmt die Erweiterung des Links das Format. Zyklen, defekte Links, unlesbare Einträge und fehlgeschlagene Dateien werden mit einer Warnung auf stderr übersprungen. Ein nicht zu öffnendes Startverzeichnis führt zu std::runtime_error. Kommentare werden nicht geladen.

Save(const std::string& path) const Speichert anhand der Erweiterung. CSV verlangt ein Array nicht leerer Maps mit gleichen Schlüsseln und Zeichenkettenwerten; ein leeres Array ergibt eine leere Datei. TOML verlangt eine Map als Wurzel und unterstützt kein null. Nicht endliche Gleitkommazahlen können nicht gespeichert werden. YAML und TOML speichern darstellbare Kommentare. Der Inhalt wird in eine temporäre Datei geschrieben und über das Ziel umbenannt; ein Schreibfehler lässt eine vorhandene Datei unverändert. Symbolische Links werden aufgelöst, Berechtigungen bleiben erhalten. E/A-Fehler und nicht darstellbare Werte oder Kommentare führen wie nicht unterstützte Erweiterungen zu std::runtime_error.

CSV verwendet die erste Zeile als Spaltennamen und speichert jede weitere Zeile als Map von Zeichenketten. Doppelte Namen und unterschiedliche Spaltenzahlen sind Fehler. YAML löst unterstützte Basisskalare auf und verwirft mehrere Dokumente, doppelte Anker, rekursive Aliase und unbekannte Tags. TOML-Datums-/Zeitwerte und nicht endliche Zahlen werden nicht geladen.

Beim Laden von CSV werden ein führendes UTF-8-BOM und Leerzeilen ignoriert; ein leerer Wert in einer einspaltigen Datei wird als "" gespeichert, damit der Datensatz erhalten bleibt. Dateipfade sind std::string-Werte in UTF-8 auf allen Plattformen, auch unter Windows; die von LoadDirectory gelieferten Namen sind ebenfalls UTF-8. Bei der Windows-DLL müssen CRT-Variante (/MD oder /MT, Debug oder Release) und _ITERATOR_DEBUG_LEVEL des Aufrufers mit der DLL übereinstimmen; andernfalls schlägt das Linken mit einem nicht aufgelösten Symbol CppDatasetUtilAbi1_* fehl.

Maps und Arrays, die tiefer als Dataset::kMaxNestingDepth (256) verschachtelt sind, werden nicht als Baum geladen. Jeder solche Wert bleibt als Zeichenkette mit seinem kompakten JSON-Text erhalten, den Parse zurückwandelt. YAML-Anker können innerhalb dieser Werte nicht definiert werden, TOML mit mehr als der doppelten Tiefe wird abgelehnt, und Save weist Werte über dem Limit zurück. YAML-Aliase, die insgesamt zu mehr als 1.000.000 Werten expandieren, sind Fehler.

BEISPIEL

#include <Dataset.h>
#include <string>
#include <variant>
Dataset data;
data["server"]["host"] = "localhost";
data["server"]["host"].set_comments({"Server address"});
data.Save("config.yaml");
Dataset loaded;
loaded.Load("config.yaml");
const auto& host = std::get<std::string>(
    loaded["server"]["host"].value());

DATENGETRIEBENE TESTS

Dieses GoogleTest-Beispiel wird im Projektverzeichnis ausgeführt. Dataset liest zwei Dateien aus Tests/data/server-config; geprüft werden Endpunkt und Status des unabhängigen ServerConfig-Modells. Die Prüfungen der Dateianzahl und der nicht leeren Fälle helfen, übersprungene Datendateien zu erkennen. Jede Datei enthält Fälle mit Eingabewerten (input) und Erwartungswerten (expected):

Tests/data/server-config/basic.json

{
  "cases": [
    {
      "input": {"host": "localhost", "port": 8080, "enabled": true},
      "expected": {"endpoint": "localhost:8080", "enabled": true}
    },
    {
      "input": {"host": "127.0.0.1", "port": 0, "enabled": false},
      "expected": {"endpoint": "127.0.0.1:0", "enabled": false}
    }
  ]
}

Tests/data/server-config/alternate.toml

[[cases]]
[cases.input]
host = "example.net"
port = 443
enabled = false

[cases.expected]
endpoint = "example.net:443"
enabled = false

#include <cstddef>
#include <cstdint>
#include <string>
#include <utility>
#include <variant>

#include <gtest/gtest.h>
#include "Dataset.h"

class ServerConfig {
 public:
  ServerConfig(std::string host, std::int64_t port, bool enabled)
      : host_(std::move(host)), port_(port), enabled_(enabled) {}

  std::string endpoint() const { return host_ + ":" + std::to_string(port_); }
  bool enabled() const { return enabled_; }

 private:
  std::string host_;
  std::int64_t port_;
  bool enabled_;
};

TEST(ServerConfigTest, BuildsEndpointAndStoresEnabledState) {
  const auto files = Dataset::LoadDirectory("Tests/data/server-config");
  ASSERT_EQ(files.size(), 2u);
  for (const auto& [path, dataset] : files) {
    SCOPED_TRACE(path);
    const auto& cases = std::get<Dataset::Array>(dataset["cases"].value());
    ASSERT_FALSE(cases.empty());
    for (std::size_t i = 0; i < cases.size(); ++i) {
      SCOPED_TRACE(i);
      const Dataset& input = cases[i]["input"];
      const Dataset& expected = cases[i]["expected"];
      const ServerConfig server(std::get<std::string>(input["host"].value()),
                                std::get<std::int64_t>(input["port"].value()),
                                std::get<bool>(input["enabled"].value()));
      EXPECT_EQ(server.endpoint(),
                std::get<std::string>(expected["endpoint"].value()));
      EXPECT_EQ(server.enabled(), std::get<bool>(expected["enabled"].value()));
    }
  }
}
