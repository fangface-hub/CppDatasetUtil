CppDatasetUtil API

NOM

CppDataSet - valeur Dataset récursive avec commentaires facultatifs

SYNOPSIS

#include <Dataset.h>
class Dataset;

DESCRIPTION

Dataset contient null, un booléen, un entier signé de 64 bits, un double, une chaîne, une table ou un tableau. Les éléments des tables et tableaux sont aussi des Dataset. Chaque valeur peut avoir ses propres commentaires. Les tables sont triées par clé et les tableaux conservent leur ordre. La copie et le déplacement conservent les valeurs et leurs commentaires.

TYPES ET CONSTRUCTEURS

Dataset::Map est std::map<std::string, Dataset>, Dataset::Array est std::vector<Dataset> et Dataset::Value est une std::variant des types pris en charge. Le constructeur par défaut crée null sans commentaire. Les constructeurs acceptent nullptr, bool, int, std::int64_t, double, const char*, std::string, Map et Array. Un pointeur null pour const char* provoque std::invalid_argument.

Tout autre type entier, comme long long, std::size_t ou unsigned, est stocké comme entier signé 64 bits ; une valeur non signée au-delà de la plage int64 provoque std::out_of_range. Les pointeurs autres que const char* sont rejetés à la compilation au lieu de devenir bool.

ACCÈS

operator[](const std::string& key) Accède à une entrée de table. Si la valeur modifiable est null, elle devient une table vide ; une clé absente est insérée avec la valeur null. Les commentaires du parent sont conservés. L'accès const ne modifie rien et lève std::out_of_range si la clé manque. Un type autre qu'une table provoque std::logic_error.

operator[](std::size_t index) Accède à un élément de tableau sans insertion. L'indice commence à 0. Un autre type provoque std::logic_error, un indice hors limites std::out_of_range. Remplacer le Dataset parent invalide les références à ses éléments.

value() const noexcept Renvoie une référence const à Value. Si le type ne correspond pas, std::get lève std::bad_variant_access et std::get_if renvoie un pointeur null.

size() const noexcept Renvoie le nombre d'entrées d'une table ou d'un tableau, et 0 pour toute autre valeur.

contains(const std::string& key) const noexcept Renvoie true si la valeur est une table contenant key.

push_back(Dataset value) Ajoute un élément à un tableau. Une valeur null devient d'abord un tableau vide et conserve ses commentaires. Tout autre type provoque std::logic_error.

erase(const std::string& key) Supprime une entrée de table et indique si elle existait. Un type autre qu'une table provoque std::logic_error.

erase(std::size_t index) Supprime un élément de tableau et décale les suivants. Un autre type provoque std::logic_error, un indice hors limites std::out_of_range.

value() noexcept Renvoie une référence modifiable à Value. Affecter une autre alternative remplace la valeur et conserve les commentaires.

operator==, operator!= Comparent récursivement valeurs et commentaires. Un NaN n'est jamais égal à lui-même.

COMMENTAIRES

comments() const noexcept Renvoie une référence const aux commentaires, dans leur ordre.

set_comments(std::vector<std::string> comments) Remplace les commentaires. Le texte ne doit pas commencer par # ; les sauts de ligne produisent plusieurs lignes de commentaire. YAML et TOML exigent UTF-8 valide et rejettent les caractères de contrôle non pris en charge et les séparateurs de ligne Unicode. Les commentaires TOML impossibles à placer sont omis. CSV et JSON ne les enregistrent pas. Une affectation ou un Load réussi remplace également les commentaires existants.

FICHIERS

Load(const std::string& path) Charge CSV, JSON, YAML ou TOML selon l'extension .csv, .json, .yaml, .yml ou .toml, sans distinction de casse. Les commentaires ne sont pas chargés. En cas de succès, la valeur et les commentaires sont remplacés ; en cas d'échec, le Dataset reste inchangé. Les erreurs d'E/S, les entrées invalides et les extensions ou valeurs non prises en charge provoquent std::runtime_error.

static Parse(const std::string& text, const std::string& format = "json") Analyse du texte CSV, JSON, YAML ou TOML. format est un nom insensible à la casse : csv, json, yaml, yml ou toml (json par défaut). Les règles, dont la limite d'imbrication, sont celles de Load, sans commentaires. Elle permet de développer la chaîne conservée pour une valeur imbriquée au-delà de la limite. Une entrée invalide ou un format non pris en charge provoque std::runtime_error.

static LoadDirectory(const std::string& path, bool recursive = false) Renvoie une std::list de paires chemin et Dataset, triée par chemin. Les sous-répertoires ne sont parcourus que si recursive=true. Les extensions non prises en charge sont ignorées. Les liens symboliques vers fichiers et répertoires sont suivis ; une cible atteinte par plusieurs chemins est chargée pour chacun. Les chemins retournés conservent les noms indiqués, y compris les liens. L'extension du lien de fichier détermine le format. Cycles, liens rompus, entrées illisibles et fichiers dont le chargement échoue sont ignorés avec un avertissement sur stderr. Un répertoire initial impossible à ouvrir provoque std::runtime_error. Les commentaires ne sont pas chargés.

Save(const std::string& path) const Enregistre selon l'extension. CSV exige un tableau de tables non vides ayant les mêmes clés et des valeurs chaîne ; un tableau vide produit un fichier vide. La racine TOML doit être une table et null n'est pas pris en charge. Les nombres flottants non finis ne peuvent pas être enregistrés. YAML et TOML enregistrent les commentaires représentables. Le contenu est écrit dans un fichier temporaire puis renommé sur la cible ; une erreur d'écriture laisse donc intact tout fichier existant. Les liens symboliques sont suivis et les permissions conservées. Les erreurs d'E/S, extensions non prises en charge et valeurs ou commentaires non représentables provoquent std::runtime_error.

En CSV, la première ligne contient les noms de colonnes et chaque ligne suivante devient une table de chaînes. Les noms répétés et les nombres de colonnes incohérents sont des erreurs. YAML résout les scalaires de base pris en charge et rejette plusieurs documents, les ancres répétées, les alias récursifs et les balises non prises en charge. Les dates, heures et nombres non finis TOML ne sont pas chargés.

Les tables et tableaux imbriqués au-delà de Dataset::kMaxNestingDepth (256) ne sont pas chargés sous forme d'arbre. Chacun est conservé comme chaîne contenant son texte JSON compact, que Parse reconvertit. Les ancres YAML ne peuvent pas être définies dans ces valeurs, un TOML imbriqué deux fois plus profondément est rejeté et Save refuse les valeurs au-delà de la limite. Les alias YAML se développant en plus de 1 000 000 de valeurs au total sont des erreurs.

EXEMPLE

#include <Dataset.h>
#include <string>
#include <variant>
Dataset data;
data["server"]["host"] = "localhost";
data["server"]["host"].set_comments({"Server address"});
data.Save("config.yaml");
Dataset loaded;
loaded.Load("config.yaml");
const auto& host = std::get<std::string>(
    loaded["server"]["host"].value());

TESTS PILOTÉS PAR LES DONNÉES

Exécuter cet exemple GoogleTest depuis la racine du projet. Dataset lit les deux fichiers de Tests/data/server-config ; l'adresse et l'état du modèle indépendant ServerConfig sont vérifiés. Les vérifications du nombre de fichiers et des cas non vides aident à détecter les fichiers de données ignorés. Chaque fichier contient des cas avec les valeurs d'entrée (input) et les valeurs attendues (expected) :

Tests/data/server-config/basic.json

{
  "cases": [
    {
      "input": {"host": "localhost", "port": 8080, "enabled": true},
      "expected": {"endpoint": "localhost:8080", "enabled": true}
    },
    {
      "input": {"host": "127.0.0.1", "port": 0, "enabled": false},
      "expected": {"endpoint": "127.0.0.1:0", "enabled": false}
    }
  ]
}

Tests/data/server-config/alternate.toml

[[cases]]
[cases.input]
host = "example.net"
port = 443
enabled = false

[cases.expected]
endpoint = "example.net:443"
enabled = false

#include <cstddef>
#include <cstdint>
#include <string>
#include <utility>
#include <variant>

#include <gtest/gtest.h>
#include "Dataset.h"

class ServerConfig {
 public:
  ServerConfig(std::string host, std::int64_t port, bool enabled)
      : host_(std::move(host)), port_(port), enabled_(enabled) {}

  std::string endpoint() const { return host_ + ":" + std::to_string(port_); }
  bool enabled() const { return enabled_; }

 private:
  std::string host_;
  std::int64_t port_;
  bool enabled_;
};

TEST(ServerConfigTest, BuildsEndpointAndStoresEnabledState) {
  const auto files = Dataset::LoadDirectory("Tests/data/server-config");
  ASSERT_EQ(files.size(), 2u);
  for (const auto& [path, dataset] : files) {
    SCOPED_TRACE(path);
    const auto& cases = std::get<Dataset::Array>(dataset["cases"].value());
    ASSERT_FALSE(cases.empty());
    for (std::size_t i = 0; i < cases.size(); ++i) {
      SCOPED_TRACE(i);
      const Dataset& input = cases[i]["input"];
      const Dataset& expected = cases[i]["expected"];
      const ServerConfig server(std::get<std::string>(input["host"].value()),
                                std::get<std::int64_t>(input["port"].value()),
                                std::get<bool>(input["enabled"].value()));
      EXPECT_EQ(server.endpoint(),
                std::get<std::string>(expected["endpoint"].value()));
      EXPECT_EQ(server.enabled(), std::get<bool>(expected["enabled"].value()));
    }
  }
}
