CppDatasetUtil API

NOME

CppDataSet - valore Dataset ricorsivo con commenti opzionali

SINTASSI

#include <cppdatasetutil.h>
class Dataset;

DESCRIZIONE

Dataset contiene null, un booleano, un intero con segno a 64 bit, double, una stringa, una mappa o un array. Anche gli elementi di mappe e array sono Dataset. Ogni valore può avere commenti propri. Le mappe sono ordinate per chiave e gli array mantengono il proprio ordine. Copia e spostamento conservano sia i valori sia i commenti.

TIPI E COSTRUTTORI

Dataset::Map è std::map<std::string, Dataset>, Dataset::Array è std::vector<Dataset> e Dataset::Value è una std::variant dei tipi supportati. Il costruttore predefinito crea null senza commenti. I costruttori accettano nullptr, bool, int, std::int64_t, double, const char*, std::string, Map e Array. Un puntatore null per const char* causa std::invalid_argument.

Qualsiasi altro tipo intero, come long long, std::size_t o unsigned, è memorizzato come intero con segno a 64 bit; un valore senza segno oltre l'intervallo int64 causa std::out_of_range. I puntatori diversi da const char* sono rifiutati in compilazione invece di diventare bool.

ACCESSO

operator[](const std::string& key) Accede a una voce della mappa. Se il valore modificabile è null, diventa una mappa vuota; una chiave assente viene inserita con valore null. I commenti del valore padre sono conservati. L'accesso const non modifica nulla e genera std::out_of_range se la chiave manca. Un tipo diverso da mappa causa std::logic_error.

operator[](std::size_t index) Accede a un elemento dell'array senza inserirlo. L'indice parte da 0. Un tipo diverso causa std::logic_error, un indice fuori intervallo std::out_of_range. La sostituzione del Dataset padre invalida i riferimenti ai suoi elementi.

value() const noexcept Restituisce un riferimento const a Value. Se il tipo non corrisponde, std::get genera std::bad_variant_access e std::get_if restituisce null. Con C++11/14 usare cppdatasetutil::get, get_if e holds_alternative (mpark/variant).

size() const noexcept Restituisce il numero di voci di una mappa o di un array, e 0 per qualsiasi altro valore.

contains(const std::string& key) const noexcept Restituisce true se il valore è una mappa che contiene key.

push_back(Dataset value) Aggiunge un elemento a un array. Un valore null diventa prima un array vuoto e mantiene i commenti. Qualsiasi altro tipo causa std::logic_error.

erase(const std::string& key) Rimuove una voce della mappa e indica se esisteva. Un tipo diverso da mappa causa std::logic_error.

erase(std::size_t index) Rimuove un elemento dell'array e sposta quelli successivi. Un tipo diverso causa std::logic_error, un indice fuori intervallo std::out_of_range.

value() noexcept Restituisce un riferimento modificabile a Value. Assegnare un'altra alternativa sostituisce il valore e mantiene i commenti.

operator==, operator!= Confrontano ricorsivamente valori e commenti. Un NaN non è mai uguale a se stesso.

COMMENTI

comments() const noexcept Restituisce un riferimento const ai commenti nel loro ordine.

set_comments(std::vector<std::string> comments) Sostituisce i commenti. Il testo non deve iniziare con #; gli a capo producono più righe di commento. YAML e TOML richiedono UTF-8 valido e rifiutano i caratteri di controllo non supportati e i separatori di riga Unicode. I commenti TOML che non possono essere posizionati vengono omessi. CSV e JSON non salvano commenti. Anche un'assegnazione o un Load riuscito sostituisce i commenti esistenti.

FILE

Load(const std::string& path) Carica CSV, JSON, YAML o TOML in base all'estensione .csv, .json, .yaml, .yml o .toml, senza distinzione tra maiuscole e minuscole. I commenti non vengono caricati. In caso di successo sostituisce valore e commenti; in caso di errore il Dataset rimane invariato. Errori di I/O, input non valido ed estensioni o valori non supportati causano std::runtime_error.

static Parse(const std::string& text, const std::string& format = "json") Analizza testo CSV, JSON, YAML o TOML. format è un nome senza distinzione tra maiuscole e minuscole: csv, json, yaml, yml o toml (predefinito json). Valgono le regole di Load, compreso il limite di annidamento, senza commenti. Serve a espandere la stringa conservata per un valore annidato oltre il limite. Input non valido o formato non supportato causa std::runtime_error.

static LoadDirectory(const std::string& path, bool recursive = false) Restituisce una std::list di coppie percorso e Dataset, ordinata per percorso. Le sottodirectory sono visitate solo se recursive=true. Le estensioni non supportate sono ignorate. I collegamenti simbolici a file e directory sono seguiti; una destinazione raggiunta da più percorsi viene caricata per ciascuno. I percorsi restituiti mantengono i nomi indicati, inclusi quelli dei link. Per un link a file, l'estensione del link determina il formato. Cicli, link interrotti, voci illeggibili e file non caricabili sono saltati con un avviso su stderr. Se la directory iniziale non può essere aperta viene generato std::runtime_error. I commenti non vengono caricati.

Save(const std::string& path) const Salva in base all'estensione. CSV richiede un array di mappe non vuote con le stesse chiavi e valori stringa; un array vuoto produce un file vuoto. La radice TOML deve essere una mappa e null non è supportato. Non è possibile salvare numeri in virgola mobile non finiti. YAML e TOML salvano i commenti rappresentabili. Il contenuto viene scritto in un file temporaneo e rinominato sul destinazione, quindi un errore di scrittura lascia invariato il file esistente. I collegamenti simbolici vengono seguiti e i permessi mantenuti. Errori di I/O, estensioni non supportate e valori o commenti non rappresentabili causano std::runtime_error.

In CSV la prima riga contiene i nomi delle colonne e ogni riga successiva diventa una mappa di stringhe. Nomi duplicati e numeri di colonne diversi sono errori. YAML risolve gli scalari di base supportati e rifiuta documenti multipli, ancore duplicate, alias ricorsivi e tag non supportati. Date, ore e numeri non finiti TOML non vengono caricati.

Durante il caricamento di un CSV, un BOM UTF-8 iniziale e le righe vuote vengono ignorati; un valore vuoto o un nome di colonna vuoto in un file a colonna singola viene salvato come "" per conservare il record. A differenza di YAML, le chiavi duplicate di un oggetto JSON non sono un errore: prevale l'ultimo valore e i duplicati nei valori annidati oltre Dataset::kMaxNestingDepth restano invariati nel loro testo JSON. Se i duplicati contano, convalidate voi stessi gli input non attendibili. I percorsi dei file sono valori std::string in UTF-8 su ogni piattaforma, Windows incluso, e anche i nomi restituiti da LoadDirectory sono UTF-8. Con la DLL Windows, la variante del CRT (/MD o /MT, Debug o Release) e _ITERATOR_DEBUG_LEVEL del chiamante devono coincidere con la DLL; in caso contrario il link fallisce con un simbolo non risolto CppDatasetUtilAbi1_*.

Le mappe e gli array annidati oltre Dataset::kMaxNestingDepth (256) non sono caricati come alberi. Ciascuno è conservato come stringa con il relativo testo JSON compatto, che Parse riconverte. Le ancore YAML non possono essere definite in questi valori, un TOML annidato oltre il doppio del limite è rifiutato e Save rifiuta i valori oltre il limite. Gli alias YAML che si espandono in più di 1.000.000 di valori in totale sono errori.

ESEMPIO

#include <cppdatasetutil.h>
#include <string>
#include <variant>
Dataset data;
data["server"]["host"] = "localhost";
data["server"]["host"].set_comments({"Server address"});
data.Save("config.yaml");
Dataset loaded;
loaded.Load("config.yaml");
const auto& host = std::get<std::string>(
    loaded["server"]["host"].value());

TEST BASATI SUI DATI

Eseguire questo esempio GoogleTest dalla radice del progetto. Dataset legge i due file in Tests/data/server-config; si verificano endpoint e stato del modello indipendente ServerConfig. I controlli sul numero di file e sui casi non vuoti aiutano a rilevare i file di dati saltati. Ogni file contiene casi con valori di ingresso (input) e attesi (expected):

Tests/data/server-config/basic.json

{
  "cases": [
    {
      "input": {"host": "localhost", "port": 8080, "enabled": true},
      "expected": {"endpoint": "localhost:8080", "enabled": true}
    },
    {
      "input": {"host": "127.0.0.1", "port": 0, "enabled": false},
      "expected": {"endpoint": "127.0.0.1:0", "enabled": false}
    }
  ]
}

Tests/data/server-config/alternate.toml

[[cases]]
[cases.input]
host = "example.net"
port = 443
enabled = false

[cases.expected]
endpoint = "example.net:443"
enabled = false

#include <cstddef>
#include <cstdint>
#include <string>
#include <utility>
#include <variant>

#include <gtest/gtest.h>
#include "cppdatasetutil.h"

class ServerConfig {
 public:
  ServerConfig(std::string host, std::int64_t port, bool enabled)
      : host_(std::move(host)), port_(port), enabled_(enabled) {}

  std::string endpoint() const { return host_ + ":" + std::to_string(port_); }
  bool enabled() const { return enabled_; }

 private:
  std::string host_;
  std::int64_t port_;
  bool enabled_;
};

TEST(ServerConfigTest, BuildsEndpointAndStoresEnabledState) {
  const auto files = Dataset::LoadDirectory("Tests/data/server-config");
  ASSERT_EQ(files.size(), 2u);
  for (const auto& [path, dataset] : files) {
    SCOPED_TRACE(path);
    const auto& cases = std::get<Dataset::Array>(dataset["cases"].value());
    ASSERT_FALSE(cases.empty());
    for (std::size_t i = 0; i < cases.size(); ++i) {
      SCOPED_TRACE(i);
      const Dataset& input = cases[i]["input"];
      const Dataset& expected = cases[i]["expected"];
      const ServerConfig server(std::get<std::string>(input["host"].value()),
                                std::get<std::int64_t>(input["port"].value()),
                                std::get<bool>(input["enabled"].value()));
      EXPECT_EQ(server.endpoint(),
                std::get<std::string>(expected["endpoint"].value()));
      EXPECT_EQ(server.enabled(), std::get<bool>(expected["enabled"].value()));
    }
  }
}
