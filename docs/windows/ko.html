CppDatasetUtil API

이름

CppDataSet - 선택적인 주석을 가진 재귀적 Dataset 값

사용법

#include <cppdatasetutil.h>
class Dataset;

설명

Dataset은 null, 불리언, 부호 있는 64비트 정수, double, 문자열, 맵 또는 배열을 보유합니다. 맵과 배열의 요소도 Dataset이며, 각 값에 주석을 따로 지정할 수 있습니다. 맵은 키순으로 정렬되고 배열은 순서를 유지합니다. 복사와 이동은 값과 주석을 함께 처리합니다.

타입과 생성자

Dataset::Map은 std::map<std::string, Dataset>, Dataset::Array는 std::vector<Dataset>, Dataset::Value는 지원 타입의 std::variant입니다. 기본 생성자는 주석이 없는 null을 만듭니다. nullptr, bool, int, std::int64_t, double, const char*, std::string, Map, Array로도 생성할 수 있습니다. const char*에 null 포인터를 전달하면 std::invalid_argument가 발생합니다.

long long, std::size_t, unsigned 등 그 밖의 정수 타입은 부호 있는 64비트 정수로 저장됩니다. int64 범위를 넘는 부호 없는 값은 2^64-1까지 부호 없는 64비트 정수(std::uint64_t)로 저장됩니다. 이 값은 JSON과 YAML에는 저장할 수 있지만 TOML에는 저장할 수 없습니다. const char*가 아닌 포인터는 bool로 변환되지 않고 컴파일 시 거부됩니다.

접근

operator[](const std::string& key) 맵 항목에 접근합니다. 변경 가능한 값이 null이면 빈 맵으로 변환하고 없는 키는 null 값으로 삽입합니다. 부모 값의 주석은 유지됩니다. const 접근은 값을 변경하지 않으며 키가 없으면 std::out_of_range가 발생합니다. 맵이 아닌 값에 접근하면 std::logic_error가 발생합니다.

operator[](std::size_t index) 배열 요소에 접근하며 삽입하지 않습니다. 인덱스는 0부터 시작합니다. 배열이 아니면 std::logic_error, 범위를 벗어나면 std::out_of_range가 발생합니다. 부모 Dataset을 교체하면 요소에 대한 참조가 무효화됩니다.

value() const noexcept Value에 대한 const 참조를 반환합니다. 타입이 다르면 std::get은 std::bad_variant_access를 발생시키고 std::get_if는 null 포인터를 반환합니다. C++11/14에서는 cppdatasetutil::get, get_if, holds_alternative(mpark/variant)를 사용하세요.

size() const noexcept 맵 또는 배열의 항목 수를 반환하며 다른 값에는 0을 반환합니다.

contains(const std::string& key) const noexcept 값이 key를 포함한 맵이면 true를 반환합니다.

push_back(Dataset value) 배열 끝에 요소를 추가합니다. null이면 먼저 빈 배열로 변환하며 주석은 유지됩니다. 그 밖의 타입은 std::logic_error가 발생합니다.

erase(const std::string& key) 맵 항목을 제거하고 존재했는지 반환합니다. 맵이 아니면 std::logic_error가 발생합니다.

erase(std::size_t index) 배열 요소를 제거하고 뒤의 요소를 앞으로 당깁니다. 배열이 아니면 std::logic_error, 범위를 벗어나면 std::out_of_range가 발생합니다.

value() noexcept Value에 대한 변경 가능한 참조를 반환합니다. 다른 타입의 값을 대입하면 값이 교체되고 주석은 유지됩니다.

operator==, operator!= 값과 주석을 재귀적으로 비교합니다. NaN은 자기 자신과도 같지 않습니다.

주석

comments() const noexcept 저장된 순서의 주석에 대한 const 참조를 반환합니다.

set_comments(std::vector<std::string> comments) 주석을 교체합니다. 앞에 #을 붙이지 않으며 줄 바꿈은 여러 주석 줄로 저장됩니다. YAML과 TOML은 유효한 UTF-8을 요구하며 지원하지 않는 제어 문자와 Unicode 줄 구분자를 거부합니다. TOML 구문상 배치할 수 없는 주석은 생략됩니다. CSV와 JSON은 주석을 저장하지 않습니다. 대입 또는 성공한 Load도 기존 주석을 교체합니다.

파일

Load(const std::string& path) 확장자 .csv, .json, .yaml, .yml, .toml을 대소문자 구별 없이 사용하여 CSV, JSON, YAML, TOML을 선택해 읽습니다. 주석은 읽지 않습니다. 성공하면 값과 주석이 교체되고 실패하면 Dataset이 그대로 유지됩니다. 입출력 오류, 잘못된 입력, 지원하지 않는 확장자 또는 값은 std::runtime_error를 발생시킵니다.

static Parse(const std::string& text, const std::string& format = "json") CSV, JSON, YAML, TOML 텍스트를 해석합니다. format은 대소문자를 구별하지 않는 csv, json, yaml, yml, toml이며 기본값은 json입니다. 중첩 한도를 포함해 Load와 같은 규칙을 따르며 주석은 읽지 않습니다. 한도보다 깊게 중첩된 값으로 유지된 문자열을 펼칠 때 사용합니다. 잘못된 입력이나 지원하지 않는 형식은 std::runtime_error를 발생시킵니다.

static LoadDirectory(const std::string& path, bool recursive = false) 경로와 Dataset 쌍을 경로순 std::list로 반환합니다. recursive=true일 때만 하위 디렉터리를 탐색하며 지원하지 않는 확장자는 무시합니다. 파일과 디렉터리의 심볼릭 링크를 따라가며 같은 대상이라도 경로마다 읽습니다. 반환된 경로는 지정된 디렉터리와 링크 이름을 유지합니다. 파일 링크의 확장자가 형식을 결정합니다. 순환, 끊어진 링크, 읽을 수 없는 항목 및 로드 실패 파일은 표준 오류에 경고하고 건너뜁니다. 시작 디렉터리를 열 수 없으면 std::runtime_error가 발생합니다. 주석은 읽지 않습니다.

Save(const std::string& path) const 확장자에 따라 저장합니다. CSV는 같은 키와 문자열 값을 가진 비어 있지 않은 맵의 배열이 필요하며 빈 배열은 빈 파일로 저장합니다. TOML의 루트는 맵이어야 하고 null은 지원하지 않습니다. 유한하지 않은 실수는 저장할 수 없습니다. YAML과 TOML은 표현 가능한 주석을 저장합니다. 내용은 임시 파일에 쓴 뒤 대상 이름으로 바꾸므로 쓰기 오류가 발생해도 기존 파일은 변경되지 않습니다. 심볼릭 링크를 따라가며 권한은 유지됩니다. 입출력 오류, 지원하지 않는 확장자, 표현할 수 없는 값이나 주석은 std::runtime_error를 발생시킵니다.

CSV는 첫 줄을 열 이름으로 사용하고 이후 각 줄을 문자열 맵으로 읽습니다. 중복 열 이름과 일치하지 않는 열 수는 오류입니다. YAML은 지원하는 기본 스칼라를 해석하고 여러 문서, 중복 앵커, 재귀 별칭 및 미지원 태그를 거부합니다. TOML의 날짜 및 시간 값과 유한하지 않은 수는 읽을 수 없습니다.

CSV를 읽을 때 맨 앞의 UTF-8 BOM과 빈 줄은 무시합니다. 한 열짜리 파일의 빈 값과 빈 열 이름은 레코드가 사라지지 않도록 ""로 저장합니다. YAML과 달리 JSON 객체의 중복 키는 오류가 아니며 마지막 값이 사용됩니다. Dataset::kMaxNestingDepth보다 깊이 중첩된 값 안의 중복은 JSON 텍스트에 그대로 남습니다. 중복이 문제가 되는 신뢰할 수 없는 입력은 직접 검증하십시오. 파일 경로는 Windows를 포함한 모든 플랫폼에서 UTF-8 std::string으로 처리되며 LoadDirectory가 반환하는 이름도 UTF-8입니다. Windows DLL에서는 사용하는 쪽의 CRT 종류(/MD 또는 /MT, Debug 또는 Release)와 _ITERATOR_DEBUG_LEVEL이 DLL과 같아야 하며, 다르면 확인되지 않은 CppDatasetUtilAbi1_* 심볼로 링크 단계에서 오류가 납니다.

Dataset::kMaxNestingDepth(256)보다 깊게 중첩된 맵과 배열은 트리로 읽지 않습니다. 해당 값은 간결한 JSON 텍스트를 담은 문자열로 유지되며 Parse로 변환할 수 있습니다. 이러한 값 내부에서는 YAML 앵커를 정의할 수 없고, 한도의 2배를 넘는 TOML은 거부되며, Save는 한도를 넘는 값을 거부합니다. 전체 1,000,000개를 넘는 값으로 확장되는 YAML 별칭은 오류입니다.

CSV 예시(쉼표, 따옴표, 줄 바꿈이 있는 필드는 "로 감싸고 내부의 "는 ""로 씁니다): 

name,age,note
Alice,30,"one, ""two""
three"
Bob,25,

예제

#include <cppdatasetutil.h>
#include <string>
#include <variant>
Dataset data;
data["server"]["host"] = "localhost";
data["server"]["host"].set_comments({"Server address"});
data.Save("config.yaml");
Dataset loaded;
loaded.Load("config.yaml");
const auto& host = std::get<std::string>(
    loaded["server"]["host"].value());

데이터 기반 테스트

다음 GoogleTest 예제는 프로젝트 루트에서 실행합니다. Dataset으로 Tests/data/server-config의 두 파일을 읽고 독립적인 ServerConfig 모델의 엔드포인트와 활성 상태를 기대값과 비교합니다. 파일 수와 빈 케이스 검사는 건너뛴 데이터 파일을 찾는 데 도움이 됩니다. 각 파일의 케이스에는 입력값 input과 기대값 expected가 있습니다.

Tests/data/server-config/basic.json

{
  "cases": [
    {
      "input": {"host": "localhost", "port": 8080, "enabled": true},
      "expected": {"endpoint": "localhost:8080", "enabled": true}
    },
    {
      "input": {"host": "127.0.0.1", "port": 0, "enabled": false},
      "expected": {"endpoint": "127.0.0.1:0", "enabled": false}
    }
  ]
}

Tests/data/server-config/alternate.toml

[[cases]]
[cases.input]
host = "example.net"
port = 443
enabled = false

[cases.expected]
endpoint = "example.net:443"
enabled = false

#include <cstddef>
#include <cstdint>
#include <string>
#include <utility>
#include <variant>

#include <gtest/gtest.h>
#include "cppdatasetutil.h"

class ServerConfig {
 public:
  ServerConfig(std::string host, std::int64_t port, bool enabled)
      : host_(std::move(host)), port_(port), enabled_(enabled) {}

  std::string endpoint() const { return host_ + ":" + std::to_string(port_); }
  bool enabled() const { return enabled_; }

 private:
  std::string host_;
  std::int64_t port_;
  bool enabled_;
};

TEST(ServerConfigTest, BuildsEndpointAndStoresEnabledState) {
  const auto files = Dataset::LoadDirectory("Tests/data/server-config");
  ASSERT_EQ(files.size(), 2u);
  for (const auto& [path, dataset] : files) {
    SCOPED_TRACE(path);
    const auto& cases = std::get<Dataset::Array>(dataset["cases"].value());
    ASSERT_FALSE(cases.empty());
    for (std::size_t i = 0; i < cases.size(); ++i) {
      SCOPED_TRACE(i);
      const Dataset& input = cases[i]["input"];
      const Dataset& expected = cases[i]["expected"];
      const ServerConfig server(std::get<std::string>(input["host"].value()),
                                std::get<std::int64_t>(input["port"].value()),
                                std::get<bool>(input["enabled"].value()));
      EXPECT_EQ(server.endpoint(),
                std::get<std::string>(expected["endpoint"].value()));
      EXPECT_EQ(server.enabled(), std::get<bool>(expected["enabled"].value()));
    }
  }
}
